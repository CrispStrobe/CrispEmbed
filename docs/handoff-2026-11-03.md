## Rules that still apply

- Gate every new path with `core_env::on` / `core_env::explicitly_off`. Never use a bare
  `getenv` presence test: `tests/test_env_vars_documented.py` fails on it. Document each new
  variable in `docs/environment-variables.md`.
- Flip a default only after an A/B against the original model, judged on decoded output and
  measured numbers. Keep the old path behind its gate.
- Run heavy work on hosted CI or Kaggle, never on a shared host. Qualification receipts use
  the portable build mode.
- CI runs only what a change needs (PR #134, `docs/contributing.md` "CI: what runs when"):
  docs/evidence-only pushes start nothing, single-engine PRs build Linux + Windows, main pushes
  with compiled changes run the full set. The account shares a small free-tier runner pool
  with sibling repos: cap sweep matrices (`strategy.max-parallel` about 4) and put multi-hour
  sweeps on Kaggle.
- Changes to `tools/quantize.cpp` or pinned Qwen3.5 sources need a recorded re-pin
  (`tools/qwen35_source_pins.py --amend`, PLAN section "Quantizer changes").
- Docs-only pushes skip the Build workflow (CI queue policy). Merge `origin/main` right before
  pushing; other agents push concurrently.
- Never put host paths or credentials in public docs.
