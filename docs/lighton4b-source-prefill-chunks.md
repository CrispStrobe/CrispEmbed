# Experimental source-boundary prefill scheduling

`CRISPEMBED_LIGHTON4B_PHYSICAL_SOURCE_PREFILL` stays default-off. It requires the admitted physical Q6 tiled CPU path. The planner derives contiguous text/image modality runs, applies the pinned server's final four-token recurrent checkpoint, and partitions logical batches into component tiles of at most16 tokens. For a logical batch of at least8, it balances a short tail so every tile remains eligible for source tiled arithmetic; logical20 becomes12+8. No image size, tensor name, token value, case label or output score selects a route.

The complete planned prompt, including an existing prefix, is bounded to512 tokens so the next upstream checkpoint516 stays outside this experiment. Ordinary hidden-cache generation retains its prior context limits. The explicit path requires modality metadata; it preserves token order and original three-axis position bits, and decoder/linear/attention cache fingerprints reject mode changes. The old uniform16 path remains when the gate is off.

This is derived from pinned [server media/checkpoint batching](https://github.com/ggml-org/llama.cpp/blob/6c01da6278ab6c69ed67d9124806b50d2b299ba7/tools/server/server-context.cpp) and its [default microbatch512/checkpoints32](https://github.com/ggml-org/llama.cpp/blob/6c01da6278ab6c69ed67d9124806b50d2b299ba7/common/common.h). Balanced component execution is not itself proof of whole-graph equivalence. Hosted arbitrary-length/position/cache controls and actual full154 source-fed QKV closure must precede observed decoded A/B. No heldout outputs were used to design this path. No recipe, default, public model alias or qualification changes.
