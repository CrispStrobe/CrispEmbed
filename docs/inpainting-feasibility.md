# Issue 71: still-image inpainting feasibility

Source-only audit, 25 October 2026. [Issue 71](https://github.com/CrispStrobe/CrispEmbed/issues/71) asks for removal of burned-in subtitles using an image and a same-size mask, with white meaning *fill*. This note evaluates that single-frame contract. It does not claim model execution, quality, backend support, or a downloadable GGUF. Exact small-file hashes and artifact metadata are in [the source contract](inpainting-source-contract.json).

## Decision

| Candidate | Source and checkpoint eligibility | Porting result |

The README also links an [author-hosted ONNX export](https://huggingface.co/andraniksargsyan/migan/tree/406830d0fa60666da0071c342ad2fbc8f30c5c64), with a declared LFS SHA. Weight reuse has explicit MIT terms with required notices; exact model identity, base-code provenance and conversion remain gates. Existing ggml convolution and image code is useful, but graph, preprocessing, and numerical parity remain unimplemented. |
| LaMa / Big-LaMa | [Upstream source](https://github.com/advimman/lama/tree/786f5936b27fb3dacd2b1ad799e4de968ea697e7) has Apache-2.0 `LICENSE`. Its README links a [third-party Big-LaMa archive](https://huggingface.co/smartywu/big-lama/tree/05cb2be7f8dbe6ca7c6e78f4fc827a4b2baaa4a9) whose card declares Apache-2.0, but neither an author-issued **checkpoint-specific** grant nor the archive's internal license/identity was verified. Hold any redistribution or model registry entry until that gap is resolved. | Higher implementation risk: Fast Fourier Convolution requires real FFT/inverse FFT and complex-channel bookkeeping. The issue's model descriptions and the LaMa model-card label are not proof of checkpoint rights or output quality. No model file was downloaded or executed for this audit.

**Base-code boundary.** MI-GAN's README says its code is built on [SH-GAN](https://github.com/SHI-Labs/SH-GAN/tree/a9ba83c5ad7dd04ba858d5067db3e6413e726b41). That pinned SH-GAN tree has an Apache-2.0 badge in its README but **no LICENSE/NOTICE file** in its tracked tree. Do not copy SH-GAN source into this port on the strength of the badge; review provenance/permission for any retained base code or implement the MI-GAN graph independently. The MI-GAN ONNX pipeline also labels its Gaussian smoothing helper as taken from [Attend-and-Excite](https://github.com/yuval-alaluf/Attend-and-Excite/tree/163efdfd341bf3590df3c0c2b582935fbc8e8343), which has an MIT `LICENSE`; preserve that notice if copying the helper, or implement the numerical operation independently. LaMa's Fourier module cites Fast Fourier Convolution; the [official FFC source](https://github.com/pkumivision/FFC/tree/39dcc992c373b0705f64d0204c4c04669381b8ea) carries Apache-2.0. These source observations do not resolve LaMa checkpoint rights.

## Original input, mask, and output contracts

**MI-GAN.** At the pinned source, [`scripts/demo.py`](https://github.com/Picsart-AI-Research/MI-GAN/blob/2b793c5ece43f4253e32d4afc257120a5deed6f5/scripts/demo.py) reads RGB, thresholds a grayscale mask to binary, resizes the image bicubically and mask by nearest neighbor to 256 or 512, then forms four channels `concat([known_mask - 0.5, normalized_rgb * known_mask])`, where RGB is in `[-1,1]`. Its *known* mask is one for preserved pixels and zero for holes. The issue's white=*fill* API therefore needs one explicit inversion before this model input. The demo converts the generator's `[-1,1]` output to uint8 and composites the known pixels from the original resized image. Its saved image can be smaller than the original because the demo first limits the long side to the model resolution.

The official [`create_onnx_pipeline.py`](https://github.com/Picsart-AI-Research/MI-GAN/blob/2b793c5ece43f4253e32d4afc257120a5deed6f5/scripts/create_onnx_pipeline.py) is a **different whole-image wrapper**: uint8 RGB `[1,3,H,W]`, uint8 grayscale `[1,1,H,W]`, 255=*known*, 0=*hole*; it finds a hole bounding box, crops with context, resizes the crop, calls the fixed-resolution generator, resizes and blends it back to original size. The README requires a binary mask. Its edge smoothing and resize choices must be frozen as part of parity; the paper's pure-generator latency does not include this wrapper. Empty masks, full-frame holes, nonbinary antialiased masks, and boundary crops need explicit behavior rather than relying on the bbox code. The Python generator registers resolution-dependent `filter_const` and `noise_const`; the README explicitly warns that the reference generator is not dynamically sized despite being conceptually convolutional.

**LaMa.** [`bin/predict.py`](https://github.com/advimman/lama/blob/786f5936b27fb3dacd2b1ad799e4de968ea697e7/bin/predict.py) loads `config.yaml` plus a selected checkpoint, uses the default validation dataset, binarizes mask values `>0`, and saves `inpainted`. [`evaluation/data.py`](https://github.com/advimman/lama/blob/786f5936b27fb3dacd2b1ad799e4de968ea697e7/saicinpainting/evaluation/data.py) loads RGB and grayscale as float `[0,1]`, CHW, and symmetrically pads both to a multiple of eight under the default prediction config, then prediction crops to original dimensions. [`trainers/default.py`](https://github.com/advimman/lama/blob/786f5936b27fb3dacd2b1ad799e4de968ea697e7/saicinpainting/training/trainers/default.py) makes the generator input `concat([image*(1-mask), mask])` and composites `mask*predicted + (1-mask)*original`. Thus LaMa directly matches white=*fill* after normalization, but the threshold, symmetric padding, tensor order and final crop are material parts of the blueprint. The default configuration has `refine: False`; refinement is a separate iterative path and is outside this first port.

## ggml coverage at CrispEmbed `ggml` submodule `890278a8342c620197c90e702e1188bcab94f510`

The pinned [`ggml.h`](https://github.com/ggml-org/ggml/blob/890278a8342c620197c90e702e1188bcab94f510/include/ggml.h) declares 2D/depthwise convolution, nearest/bilinear interpolation, elementwise arithmetic, leaky ReLU, pooling, padding, and a constrained transposed convolution. CrispEmbed already uses 2D/depthwise convolution in `src/restormer.cpp` and has image-in/image-out engines. This is **API/graph feasibility**, not a CPU/Metal/CUDA kernel or performance certification.

MI-GAN's pinned [`migan_inference.py`](https://github.com/Picsart-AI-Research/MI-GAN/blob/2b793c5ece43f4253e32d4afc257120a5deed6f5/lib/model_zoo/migan_inference.py) uses depthwise 3×3 then pointwise 1×1 convolutions, learned features and skip connections, a fixed 4×4 depthwise downsample, nearest doubling followed by a zero-insertion `filter_const` and depthwise filter, and optional checkpoint noise. Porting must reproduce operation order, asymmetric `(2,1,2,1)` pad, channel layout, constants, activation gain/clamp, and output blending. Do not drop noise merely because its parameter initializes to zero; inspect the chosen checkpoint first.

LaMa's [`big-lama.yaml`](https://github.com/advimman/lama/blob/786f5936b27fb3dacd2b1ad799e4de968ea697e7/configs/training/big-lama.yaml) declares 18 FFC residual blocks with 75% global channels. [`ffc.py`](https://github.com/advimman/lama/blob/786f5936b27fb3dacd2b1ad799e4de968ea697e7/saicinpainting/training/modules/ffc.py) applies `torch.fft.rfftn`/`irfftn` with orthogonal normalization, real/imag channel packing, 1×1 convolutions and batch norm in frequency space. The pinned ggml header declares no rFFT/iFFT primitive; its `ggml_pad_reflect_1d` does not directly establish LaMa's 2D reflection behavior, and its transposed-convolution helper is restricted to zero padding whereas the LaMa decoder config uses padding/output-padding. Those are porting tasks, not a proof of impossibility; any custom or decomposed implementation would require backend-specific parity and memory checks.

## Bounded follow-up gates

1. **Model/source receipt:** choose one MI-GAN resolution and exact checkpoint/export. Verify the payload SHA, tensor inventory, architecture/config correspondence, explicit MIT weight notice and any copied base/helper source notices. For LaMa, obtain authoritative checkpoint terms and verify archive contents and SHA before conversion or distribution.
2. **Still-image reference:** freeze same-size RGB/mask pairs with white=*fill*, including subtitle strips, edges, empty/full masks and nonbinary inputs. Capture original preprocessed tensors, block outputs, final RGB, dimensions and known-pixel preservation. Define parity and quality thresholds before native results; preserve failing examples and decoded image artifacts remotely.
3. **Native/API qualification:** export a GGUF only after tensor mapping and F32 original/native stage comparison; then test CPU and each claimed backend, F16/quantization separately, finite outputs, mask polarity, seams, quality, latency and peak memory. Keep reference probes out of distributed weights and do not add a registry alias before exact artifact/review receipts.
4. **Video is a separate lane:** batch or stdin-list should load one model for many frames and preserve ordering/error records. A static subtitle span may reuse a single completed background only when registration, camera motion, occlusion and temporal drift checks permit it. Per-frame independent completion can flicker; neither static-span reuse nor temporal propagation is established by a still-image result. Text detection/dilation and region limiting likewise need separately frozen mask contracts.

**Result of the25 October source-only audit:** source-level feasibility only. No issue closure, production model, publication, API change, temporal claim, or quality conclusion follows from this audit.
