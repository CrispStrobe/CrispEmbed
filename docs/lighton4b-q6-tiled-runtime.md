**Unqualified: keep all experimental gates default-off; do not ship.** The fixed GDN/Q4-repack/Q6-tiled corrected configuration still misses the historical receipt floor: 25/768 content character edits and 19/144 word edits versus upstream 24/768 and 18/144. Corrected pixels and source-feature arms both finish with 468 IDs/EOS and identical raw score rows. The old baseline (469 IDs/EOS) has the same edit counts. [Verified full result and independent raw audit](https://github.com/CrispStrobe/CrispEmbed/blob/0c312ec43ac6f3bba5376df32bbe5f80e78e9230/docs/lighton4b-q6-heldout-provisional-results.md) preserve this failure; passing observed cases cannot waive it.

`CRISPEMBED_LIGHTON4B_PHYSICAL_Q6_TILED` stays default-off. The physical LightOn4B owner admits it only in the previously closed native CPU profile and with native layer projections enabled. It applies the pinned upstream Q6 block reduction generically to eligible batches of at least eight tokens, preserves legacy arithmetic below that threshold, and rejects cache reuse across modes. Original quantized weights, Q4 repack policy, HF profiles, public model fences and aliases remain unchanged.

The implementation reproduces the upstream integer block sum, weight-scale multiply and explicit activation-scale FMA without an expanded F32 weight cache. The [source-fed proof](https://github.com/CrispStrobe/CrispEmbed/blob/3c5f19c654d06ca3e0b52172f8f88e13c4e95386/docs/lighton4b-q6-tiled-helper-results.md) closes all 68 retained native/upstream operator outputs and every actual 140-row QKV output byte-exactly.
