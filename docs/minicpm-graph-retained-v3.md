## Canonical retention and quota

The23 old inventories total20,716,681,339B. Of that,13,912,044,352B is duplicate raw-prefill/GGUF/probe storage; canonical native dumps, sampled control/native projection outputs and scalar/log evidence total6,804,636,987B. The old service is read-only and never cleaned. Hosted compaction reconstructs omitted whole GGUF/raw hashes from authenticated canonical NPY/raw sources, source83 header/alignment/order rules and exact logical shapes. It retains each source/payload/adapter identity and reconstruction recipe before copying the compact canonical bundle. A failed reconstruction rejects compaction.

New original/native F32 adapter copies and GGUFs live in task-owned scratch. Actual Ref results/logs, independent metrics and lossless readback/reconstruction manifests must be durable before the helper removes only the two adapters it just created. Full-prefill probe duplicates are removed only after their raw hashes match canonical NPY payloads and a reconstruction manifest is written. Canonical dumps, sampled projection outputs, original arrays, models and unrelated files are never deletion targets. No complete tensor `tobytes()` is used by the streaming old-adapter hash reconstruction.

Working-output admission is separate from scratch free space. The source contract caps retained output at12GiB with4GiB free reserved for receipts/notebook finalization, checks a conservative2GiB next-arm bound, and retains the original10GiB available-RAM/32GiB scratch admission. Resource checks repeat before work; standard GHA capacity is not assumed. JSON receipts use temporary-file flush/fsync/atomic replacement so a failed new write cannot truncate the last valid receipt. Partial canonical dumps survive controlled failures and termination. Remote artifacts retain90 days; arrays/models are never downloaded to a constrained local host.
