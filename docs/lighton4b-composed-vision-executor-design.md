# Composed vision admission before provisional held-out execution

This is a prospective execution design, not a result or an inference submission. Current source-feature decoder results are not end-to-end evidence. Finish the extended observed-table comparison before freezing any new execution bundle; do not silently retune the held-out protocol using its results.

Use the already observed simple form, simple table and Arabic line, in that order. Keep their immutable input bytes, actual RGB, prompt wrapper/token IDs, geometry and positions from the existing physical protocol. Preserve current table256 results and any separately admitted512 extension. Freeze one cap per case for all compared arms before outputs. A capped arm remains incomplete. Never substitute an unobserved case for a failed observed case.

For each case run pinned upstream projector+decoder observer OFF/ON, native decoder with authenticated upstream merged features (diagnostic), and native composed vision+the identical native decoder (primary). Use the same physical text payload, runtime executable/libraries, gate tuple, threads, context and independent greedy settings; the sole native arm difference is source features versus composed vision. Clear inherited CRISPEMBED settings before applying the frozen tuple. Require observer OFF/ON complete IDs/text/probabilities/EOS neutrality and exact prompt/modalities/position closure before interpreting differences.

Authenticate the publisher F16 projector and native protected vision weights separately. Map each patch embedding, block norm/QKV/out/FFN, merger norm and merger projection tensor to its canonical layout; hash canonical values and record dtype/rounding differences. Do not claim equal projector weights from matching text matrices or an image embedding cosine. Native BF16-derived protected parameters versus publisher F16 mmproj can be a real weight/dtype confound. If canonical identity is not proven, call the comparison “deployed projectors on identical RGB”, not a pure arithmetic comparison. No full F32 model is required.

Capture preprocessing patches/grid, patch projection+position/rotary inputs where observable, every visual block output, merger output, prompt splice, all32 text block outputs, final norm and first-score row. Recompute raw hashes and FP64 RMS/max/absolute errors from retained arrays. Only compare stages with equivalent layout and declared observable semantics; missing upstream intermediates remain unsupported. Report the earliest comparable differing stage and magnitude, and distinguish projector differences from subsequent text propagation. Source-fed operator attribution is a separate control, not proof of composed parity.

Retain complete independent greedy IDs/raw UTF-8, EOS/cap, every row hash/argmax, resources and partials for each arm. Compare against existing independent annotations where available, with their explicit reference limitations, and separately against actual upstream text. Do not call a BF16 output ground truth or infer character accuracy from first-score RMS. No release qualification follows from this observed-case panel; it is development evidence and a prerequisite to the frozen provisional held-out panel.

Implementation order: (1) asset/provenance and supported-geometry admission; (2) source-neutrality and composed/source-feature input closure; (3) same-native-decoder paired projection/greedy execution on observed cases; (4) independent artifact review; (5) generic held-out cap1536 executor with context2048/prompt<=512 controls. Keep reference probes and loader logging out of production artifacts, default gates off, and the public loader closed.

The initial source in tools/heldout/lighton4b_prepare.py performs only frozen input/reference admission and emits a blocked plan. It deliberately cannot invoke processes or acquire models. A future hosted execution adapter must add complete whole-worker/group deadlines and per-arm resources, an immutable binary/gate/prompt bundle, non-overwriting output directories, and raw partial receipts before becoming runnable. This document does not authorize or launch such an adapter.
