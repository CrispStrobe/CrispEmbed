## Working rules (apply to every task below)

- Work in an isolated git worktree based on `origin/main`; commit and push branches.
  The owner allows merging straight to `main` without a PR once the work is verified.
- **No inference, model downloads or full builds on the shared development host**
  (tight memory/load). Syntax-only compiles (`nice g++ -fsyntax-only`) and small unit
  tests are fine. Run models on **Kaggle CPU kernels** (preferred while the GitHub
  queue is long) or hosted CI. Kaggle pattern: `tools/kaggle/<name>/` with
  `kernel.py` (a script kernel that clones the repo at `@COMMIT@` and builds inside a
  uv Python 3.12 venv) plus `kernel-metadata.json`. The metadata **title must equal the
  slug**, otherwise the push fails with HTTP 409. To push: substitute `@COMMIT@` and
  `${KAGGLE_ACCOUNT}` in a scratch copy, then run `python3 -m kaggle kernels push -p DIR`.
  At most 5 concurrent CPU sessions. Download only small outputs:
  `kaggle kernels output … --file-pattern '.*\.(json|md)$'`.
- **New model runtimes:** take every preprocessing/architecture detail from the pinned
  upstream Python source and cite file:line in the spec — never guess or leave
  alternative switches. Study existing ggml/llama.cpp ports (check their license) only
  to learn; do not copy code. Before writing a component, inventory and reuse what the
  codebase already has (vision blocks, torch/PIL-exact resizers, qwen35 decoder fast
  paths, loaders, dumps, dispatch) and generalize shared code without changing other
  engines' behavior.
- Gates: new paths default-off via `core_env::on()`; A/B by decoded output against the
  original before any default flip; keep old paths.
- **Code that must compile on MSVC:** use `static constexpr` locals in lambdas (no
  implicit capture). Do not grow the CLI option `else if` chain in
  `examples/cli/main.cpp`, which is already split for C1061; add new flags to the second
  chain. Every test `main()` must route through `core_util::clean_exit` (Static guards).
  Use anonymous namespaces for TU-local structs (an ODR clash bit us before). Format
  with `clang-format-18` via `tools/format.sh`.
- **Declaration re-pins:** any commit on main that changes `src/`, `CMakeLists.txt`,
  `examples/` or an individually declared source file invalidates the Ovis
  final-integrated v2 and successor-assets v2 pins.
  1. Commit the change.
  2. Run `tools/redeclare_final_v2.py`. It rewrites only the five v2 files; `--check`
     reports staleness.
  3. Commit, then run `python3 tests/test_ovisocr2_final_integrated_v2.py` and
     `tests/test_successor_assets_v2.py`.
  4. Push, cancel stale runs, and re-dispatch:
     `gh workflow run ovisocr2-metadata.yml --ref main -f phase=final-integrated-v2` and
     `gh workflow run successor-assets-v2.yml --ref main -f corpus_run=40629090339`
     (the corpus run must have been produced from the current
     `tools/probe_posformer_release.py`).

  Batch `src` changes into one push: every push to main also cancels the running Build.
- HF publishing: GitHub workflows with the `HF_PUBLISH_TOKEN` secret. Preserve upstream
  licenses (verbatim LICENSE pinned by sha256, attribution, statement of changes,
  upstream card as `UPSTREAM_README.md`). A workflow must be on main to be dispatched.
